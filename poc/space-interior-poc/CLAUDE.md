# CLAUDE.md

Guidance for Claude Code when working in this PoC.

## Commands

```bash
npm start                         # ng serve → http://localhost:4430
npm run kit                       # rebuild slim GLBs + kit-models.generated.ts from resources/
npx ng test --watch=false         # unit tests (vitest + jsdom)
npx vitest run src/app            # domain + built-model tests, no Angular build (fastest loop)
npm run check                     # tsc + tests + production build
```

`.npmrc` sets `legacy-peer-deps=true` (same npm arborist issue as `space-3d-poc`). `@space-game/hud-design-system` is `file:../../design-system`; only its CSS is used.

## Project

Grid editor for ship/station interiors on the Molten Maps SciFi kit (CC0, `resources/Molten Maps SciFi Asset Pack`). Design rationale and the survey of analogous games/tools: `ANALIZA.md` (Polish, binding). UI text is Polish.

## Architecture

`ui → state → domain ← engine`. `domain/` imports nothing from `@angular/*` or `three` and holds all rules and all tests.

- **Grid** (`domain/grid.ts`):
  - Cell = 4 m. Edges carry walls/doors/glass/railings.
  - Axis-`x` edge (x, z) runs from vertex (x, z) to (x+1, z); axis-`z` edges work the same way along Z.
  - Level height is 4 m. Objects snap to 0.5 m.
  - `rot` is quarter turns about +Y. A model's front is local +Z, so a wall with rot 0 faces +Z.
  - `rotateXZ` matches Three.js `rotation.y`.
- **Document** (`domain/layout.ts`):
  - A flat map of `Piece {id, item, level, x, z, rot}`. `item` is a catalog variant id (`entry/variant`).
  - Edits are `Change {add, remove}` with full piece copies. `history.ts` undoes by inverting.
  - Ids are `p<n>` from `layout.seq`.
- **Catalog** (`domain/catalog/`):
  - `catalog.ts` says what each kit model MEANS: placement kind (`floor`, `ceiling`, `edge`, `object` with layer `floor | surface | wall | ceiling`), room-type tags, ship stats.
  - `kit-models.generated.ts` holds measured bounds. It is generated by `npm run kit` — never edit it by hand.
  - `models.ts` adds the models the kit lacks (`PROC_MODELS`: lift stop, stairs with steps), which `engine/proc-models.ts` builds from boxes sampling the kit atlas. `MODELS`/`ModelId` cover both. Change a built model's geometry → update its bounds/tris in `models.ts`; `proc-models.spec.ts` fails otherwise.
- **Decks** (`connector` on a floor placement):
  - `'stairs'`: kit ramps and the built stairs. They rise towards local −Z, so you enter from the front cell (`grid.stairsLink`) and arrive one deck up on the cell behind. `planStairs` also opens the deck above (drops its floor tile and the ceiling below) and rails the opening, except the arrival side.
  - `'lift'`: one stop per deck. `planLift` puts a door on the front and glass on the free sides. Stops in the same cell on adjacent decks form a shaft (`LayoutIndex.liftShaft`).
  - `LayoutIndex` keeps `stairs`, `stairTops` (arrival edges, never drops), `openings` and `lifts`.
  - `rooms.roomLinks` joins rooms by doors, stairs and lifts; reachability uses it.
  - The editor offers decks 0…`MAX_DECK` (3).
- **Derived data.** `LayoutIndex` (occupancy) → `rules.checkPlacement` (the only place placement rules live) → `rooms.computeRooms` (flood fill; walls/doors/glass split rooms, railings do not) → `validation.computeIssues` → `stats.summarize`. All of them are `computed` in `EditorStore`. Never store them.
- **Planners** (`domain/planners.ts`):
  - Turn a gesture into a `Plan {change, rejected, reason}` without applying it.
  - `withCascade` adds pieces that lose support (furniture on a removed floor, a wall item on a wall replaced by a door) to the same change.
  - The same plan drives the ghost preview and the committed command.
- **Engine** (`engine/`):
  - `KitMaterials`: 5 shared materials, one atlas, plus a cutaway shader patch (`aCutY` per instance; fragments above it are discarded; 0 = no cut).
  - `KitLibrary`: loads slim GLBs and flattens each to one geometry with material groups.
  - `LayoutView`: one growing `InstancedMesh` per model, synced from the index.
  - Also `GhostView`, `OverlayView` (grid, outlines, issue strips), thumbnails.
  - `CameraRig`: LMB is reserved for tools; MMB rotates, RMB pans.
    - Alt + LMB rotates too: a capture-phase listener switches OrbitControls' left button for that gesture, and the viewport keeps it from the tools. Shift/Ctrl + RMB rotate (OrbitControls' own behaviour).
    - `heading` is the camera azimuth (0 = looking at −Z, "north" up). `turnBy` (45° steps), `turnTo` (eased) and `orbitBy` (immediate) all go through it.
    - `ui/view-compass.ts` is presentational: the viewport mirrors `heading` and `topDown` into signals each frame and turns the camera on its events.
  - Lighting: day and night are a `LightingPreset` (`engine/lighting-presets.ts`, plain data with no Three.js, so the store can read it). Night was tuned against the kit's `Layout Example Dark.png`; keep its numbers unless you re-measure.
  - Night tuning:
    - `EditorStore.nightTuning` is a diff against the reference night, persisted per browser (`space-interior-poc:night`). It is edited in `ui/night-panel.ts` and passed in by `engine.setLighting(mode, tuning)`.
    - `engine.tune({...})` still works from the dev console (`window.__interior.engine`).
  - Emitters are catalog data: `light` on an entry, resolved by `lightOf()`. Variant colour applies, and variants keyed `off` give no light.
  - A fixed pool of `LIGHT_POOL_MAX` (32) `PointLight`s, `preset.lights` of them visible (default 20), goes to the emitters that matter most for the view. Changing `lights` recompiles shaders once.
  - Lower decks' lights count only where no visible deck above covers them.
  - Ceilings and ceiling-layer objects are visible only with `showCeilings`.
  - **Gotcha:** geometries made by `shareGeometry()` must be freed with `disposeShared()`. Plain `dispose()` deletes the model's shared GL buffers.
- **State** (`state/`):
  - `EditorStore` is the only place state mutates.
  - `ToolController` maps pointer gestures to planners. With a stairs or lift item, the floor tool places one cell (with `planStairs` / `planLift`) instead of painting a rectangle.
  - `roomFloorItem` (what the room tool lays) only takes plain floors. `floorItem` may be stairs, a lift or a ceiling.
  - Viewport effects read `engineRef()` first. A call like `engine?.fn(signal())` skips the read while the engine is missing, and the effect then never re-runs.

## Conventions

- Rules change in `rules.ts` / `rooms.ts` / `validation.ts`, with a test in `domain.spec.ts`. `sample-layout.spec.ts` must stay issue-free.
- New kit models: add a catalog entry (with variants); bounds come from the generated table.
- Styling follows `design-system/README.md`:
  - amber signal colour only for interaction and important data, red only for critical states,
  - radius 0, no shadows or transitions,
  - JetBrains Mono, uppercase labels.

  Editor CSS lives in `src/styles/editor.css`.
